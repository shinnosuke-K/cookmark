# Cookmark 機能仕様

夫婦2人でInstagramのレシピ投稿を共有・管理するモバイルPWA。InstagramのDMでレシピを送り合うと「どれを作ったか/まだか」が分からなくなる課題を解決する。本書は現在実装済みの全機能・全画面・主要文言をまとめた仕様の記録。

## プロダクトの性格

- 利用者は夫婦2人だけ。ストア公開・一般公開はしない。アカウント登録なし(匿名認証+招待URL)
- コアループ: ①インスタでレシピを見つけリンクをコピー → Cookmarkで貼り付けて追加(未挑戦リストへ) → ②作ったら「作った!」を1タップ → 「リピート確定/イマイチ」の2択を即答 → ③「リピート確定」フィルタが夫婦の定番レシピ集に育つ
- デザイン原則:
  - **登録の摩擦を最小に**。追加とステータス変更は最短タップ数を最優先
  - **入力ゼロでも探せる**。自動で付く情報(ステータス・追加者・日付)だけで絞り込みが成立。タグは固定チップのみ
  - **静かな道具**。通知なし、リアルタイム同期なし、バッジなし。開いたときに最新ならよい
  - **Instagram連携はベストエフォート**。自動取得が失敗しても手動入力で常に成立する

## デザイン制約

- モバイルファースト(想定利用はほぼスマホ、PWAとしてホーム画面から起動)
- 最小フォントサイズ **14px**、タップターゲット **44px以上**
- **ライトテーマ固定**(ダークモード非対応、意図的)
- UIテキストは日本語。トーンは簡潔・フレンドリー(「作った!」「今夜どうする?」)
- ビジュアルは新聞紙面風の **Broadsheet** デザインで実装済み: Source Serif 4(和文はセリフフォールバック)、紙白地 #f3f2f2、アクセントはシアン #0088b0(インタラクティブ要素)とマゼンタ #d6006c(リピート確定・削除系)、アイコンは Phosphor duotone。罫線・カードで区切らず、セリフの級数差と余白で階層を作る(トークンは app/globals.css)
- 画面下部に固定タブバー(4タブ)。招待参加画面(/join)だけはタブバーなしの単独完結画面

## データモデル(UIに表示される属性)

レシピ1件が持つ表示属性:

| 属性 | 値 | 備考 |
|---|---|---|
| タイトル | 自由入力(必須) | 例: 鶏むね肉のねぎ塩レモン |
| Instagram URL | 任意 | ある場合、詳細画面でembed表示+「Instagramで開く」リンク |
| 投稿者ハンドル | 任意 | 「@foodie_taro」形式で表示 |
| ステータス | 未挑戦 / 作った | 共有ステータス1つ(どちらが作ったかは区別しない) |
| 評価 | リピート確定 / イマイチ / 未評価 | 「作った」のみ。星評価はしない(2択即答が原則) |
| カテゴリ | 主菜・副菜・汁物・麺・丼・おやつ の5固定チップ(任意・単一選択) | |
| メモ | 任意 | 味付けメモなど |
| 写真 | 任意(ユーザー撮影) | リストのサムネイルにも使用。なければプレースホルダー |
| 追加者 | 表示名(例: 夫、妻) | 「夫が追加」形式で表示 |
| 作った回数 | cook_count(初回の作った!で1、「また作った!」で加算) | 詳細に「◯回作った」、アーカイブのリピート確定バッジに ×N |

## 画面構成

タブバー: **ホーム / アーカイブ / 今夜 / 設定**(Phosphor duotone: fork-knife / books / moon-stars / sliders-horizontal + 14pxラベル)

### 1. ホーム(未挑戦リスト)`/`

**参加済みの場合:**
- 画面下部・タブバー直上に「**貼り付けて追加**」のフローティングピル(このアプリの最重要CTA)
  - タップするとクリップボードを読み、InstagramのURLがあれば解析して追加フォームを事前入力して開く。読めなくてもエラーにせず空のフォームを開く
  - URLがあれば裏で自動取得(/api/og)が走り、タイトル・投稿者を未入力の間だけ事前入力。URL欄への手入力でも600msデバウンスで同様に取得。追加確定後はキャプションをメモへ、投稿画像を圧縮してサムネイルとして自動添付(すべてベストエフォート・失敗は無言)
  - 追加後、フォームは常にクリーンな状態で開き直す。直前に追加したのと同じURLがクリップボードに残っていても再事前入力しない
- 未挑戦レシピのカードリスト(新しい順)。カード要素:
  - サムネイル(写真 or プレースホルダー)/ タイトル / 「夫が追加」/ カテゴリチップ / **「作った!」ボタン**
  - カード本体タップ → 詳細画面へ。「作った!」ボタンはカード遷移と独立
- 空状態: 「レシピはまだありません」「上のボタンから追加しましょう」

**未参加(初回)の場合(ウェルカム画面):**
- 「Cookmarkへようこそ」「夫婦でInstagramのレシピを共有・管理するアプリです」
- 名前入力(プレースホルダー「例: 夫、妻」)+「新しくボードを作る」ボタン
- 補足文: 「パートナーがすでにボードを作っている場合は、届いた招待URLを開いて参加してください」

**追加フォーム(モーダル/ボトムシート、貼り付けボタン・共有シート両方から開く):**
- 見出し「レシピを追加」
- InstagramのURL(任意)/ タイトル(必須、プレースホルダー「例: 鶏むね肉のねぎ塩レモン」)/ カテゴリ(任意、5チップ単一選択)/ 投稿者ハンドル(任意、「例: foodie_taro」)
- 「キャンセル」「追加する」(送信中は「追加中...」)
- 成功トースト「レシピを追加しました」

### 2. 作った!フロー(ボトムシート)

ホームのカードで「作った!」をタップすると開く。**このアプリで最も大事にしている体験**——2択を大きく、即答できること。

- レシピタイトル+「また作りたい?」
- 大きな2択ボタン: 「**リピート確定**」「**イマイチ**」
- 任意入力: メモ(任意)(プレースホルダー「味付けのメモなど」)/ 写真(任意)
- どちらかを押すと即保存してシートが閉じ、アーカイブ画面へ自動遷移する(レシピもアーカイブへ移動)
- **選ばずに閉じた場合も「作った」は確定**(未評価として保存)。評価はあとから詳細画面で変更可能
- 写真アップロード失敗時のトースト: 「写真のアップロードに失敗しました。他の内容は保存します」

### 3. アーカイブ(作った一覧)`/archive`

- 見出し「アーカイブ」
- **「リピート確定のみ表示」トグル**(目立つ位置に。定番レシピ集への入口)
- フリーワード検索(プレースホルダー「タイトル・メモで検索」、タイトル+メモ対象)
- カテゴリチップで絞り込み(5チップ)
- カードリスト(作った日の新しい順)。行要素: サムネイル / タイトル / 追加者 / 色付きカテゴリタグ / **評価バッジ(リピート確定 ×N / イマイチ / 未評価)**
- 空状態: 「作ったレシピはまだありません」/ 絞り込み結果ゼロ: 「条件に合うレシピがありません」

### 4. 今夜どうする `/tonight`

- 見出し「今夜どうする」
- 抽選元の切り替え(セグメント): 「**未挑戦から**」/「**リピート確定から**」
- ランダムに1件をカードで提案(タイトル / 投稿者 / カテゴリ / 提案元)
- 「**別のにする**」ボタンで引き直し(直前と同じものは出ない。候補が1件だけなら「他の候補がありません」トースト)/「詳しく見る」で詳細へ
- 空状態: 「未挑戦のレシピがありません」/「リピート確定のレシピがまだありません」

### 5. レシピ詳細 `/recipe/[id]`

- 「← ホームへ戻る」
- タイトル / @投稿者 / ステータス・評価バッジ(未挑戦 / リピート確定 / イマイチ / 作った(未評価))。**写真は表示しない**(サムネイル専用)
- **Instagram埋め込み**(URLがある場合のみ)。高さ60vh(最大600px)でiframe内を上下スクロールでき、投稿の画像+キャプション全体を読める。画面内に入ったら遅延ロード。読み込み失敗時はエラーを出さず静かに非表示(プレースホルダー「Instagram投稿」)。「**Instagramで開く**」外部リンク
- **編集セクション**: タイトル / カテゴリ(5チップ)/ メモ / 評価(作った済みのみ: リピート確定・イマイチのチップ、再タップで未評価に戻す)、「保存する」(保存中は「保存中...」、成功トースト「保存しました」)
- **リピート記録**: 「◯回作った」表示と「**また作った!**」ボタン(押すと回数を加算、トースト「◯回目を記録しました」)
- 「**削除する**」(確認ダイアログ「このレシピを削除しますか?元に戻せません」→ 削除後ホームへ、トースト「削除しました」)
- レシピが存在しない場合: 「レシピが見つかりません」

### 6. 設定 `/settings`

- 見出し「設定」
- 表示名(読み取り専用表示)
- **招待URL**(このアプリの生命線。iOSでセッションが消えたときの復帰経路のため常時表示):
  - 説明文「このURLをパートナーに送るとボードに参加できます。iOSでアプリのデータが消えてログインできなくなった場合も、このURLからもう一度参加できます。」
  - URL表示欄+「コピー」ボタン(押すと「コピー済み」、トースト「招待URLをコピーしました」)
  - 「**招待URLを再発行**」(確認ダイアログ付き)。以後、古いURLでは参加できなくなる(参加済みメンバーはそのまま)

### 7. 招待参加 `/join/[token]`(タブバーなしの単独画面)

- 「招待されたボードに参加します」
- 名前入力(「あなたの名前」、プレースホルダー「例: 夫、妻」)
- 「参加する」(参加中は「参加中...」)→ 成功トースト「ボードに参加しました!」→ ホームへ
- 失敗トースト「参加に失敗しました。招待URLをもう一度確認してください」

## 状態・フィードバックの原則

- ローディングは各画面「読み込み中...」の軽い表示(スケルトンは使わない)
- 成功・失敗はすべてトースト(画面上部中央のダークピル、約2.2秒で自動消滅)。**例外はInstagram埋め込みと自動取得の失敗のみ無言**
- 通知・バッジ・リアルタイム更新は存在しない(意図的仕様。デザインにも入れない)

## やらないこと(デザインにも含めない)

- プッシュ通知・リマインダー、既読/未読バッジ
- 星評価・自由入力タグ(評価は2択+未評価の3状態のみ)
- 夫婦それぞれの「作った」個別管理(ステータスは共有1つ)
- ログイン画面・プロフィール画面(匿名認証のため存在しない)
- 3人以上の共有UI、多言語対応、ダークモード
